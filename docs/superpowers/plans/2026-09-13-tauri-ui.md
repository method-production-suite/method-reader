# Tauri interface (piece D) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace `desktop/ui/`'s placeholder with the real Screepub interface — Convert, Read, Tune, Send, Notes — built from `brand/`'s finished identity, on the piece-C shell.

**Architecture:** The window is static HTML/CSS/ES modules under `desktop/ui/`, embedded by `tauri-build` (no bundler, no npm, no dev server). All thinking stays in TypeScript: the window builds an argv, hands it to `run_engine`, and renders the engine's own JSON. Four small CLI additions give the window the reach the five surfaces need — the shell has no channel to the engine other than argv and stdout. The one Rust change streams the engine's stderr as an event; it adds no command and parses nothing. The reader renders the engine's own `tokensToPreviewHtml` in a sandboxed same-origin `srcdoc` iframe whose stylesheet is adopted through CSSOM, which keeps the strict CSP intact.

**Tech Stack:** Bun/TypeScript engine; Tauri 2.11 / tauri-plugin-shell 2.3 / Rust 1.98; WebKitGTK (Linux), WKWebView (macOS), WebView2 (Windows); plain ES modules and CSS custom properties; Courier Prime + Literata as bundled WOFF2 subsets.

**Spec:** `docs/superpowers/specs/2026-09-13-tauri-ui-design.md` (program: `docs/adr/2026-09-12-cross-platform-tauri.md`; predecessor: `docs/superpowers/specs/2026-09-13-tauri-shell-design.md`)

## Global Constraints

- **Rust is a window, not a brain.** No business logic in Rust — not device detection, not transfer, not settings, not conversion.
- **No new Rust command.** The registered commands stay exactly `pick_file` and `run_engine`. `desktop/`'s non-comment Rust line count stays at or below piece C's ceiling of **200** (59 today; 75 after Task 5).
- **Nothing under `app/` may be modified.**
- **`tests/brand-tokens.test.ts` and `tests/brand-components.test.ts` must pass unmodified.** If a token needs changing, change `brand/tokens.json`, not the app.
- **The engine suite stays green** — 968 pass / 3 skip / 0 fail is today's baseline — and `bunx tsc --noEmit` stays clean.
- **Every colour and size comes from the brand tokens.** A reviewer grepping `desktop/ui/` for a hard-coded hex finds none outside the two generated/pinned token blocks.
- **D invents no palette and no typeface.** `brand/tokens.css`, `brand/tokens.json` and the twelve components in `brand/components/` are the design; D composes them.
- **The window is usable at a small size and with the keyboard, and respects reduced motion.**
- **Errors say what happened and what to do.** The engine's own message is rendered verbatim, never reworded into an apology. Verbs stay constant through a flow: Send produces Sent.
- **`--json` contract:** every engine exit in `--json` mode prints exactly one parseable JSON object on stdout. Progress and diagnostics go to stderr only.
- **CSS in `desktop/ui/` is website CSS, not EPUB CSS.** `var()`/`clamp()` are correct here; CLAUDE.md's CSS-2.1 ban applies to `src/epub/css.ts` only.
- **Out of scope (explicitly):** bundling and installers (E2), retiring the SwiftUI app (F), auto-update, anything needing a signing certificate, new device capabilities.

## What was measured before this plan was written

Every claim below was observed on this machine (aarch64-unknown-linux-gnu, Tauri 2.11.5, WebKitGTK, rustc 1.98.1, bun 1.3.11) by building and running the real shell. They are the load-bearing facts; do not re-derive them, but do re-check them if something behaves differently.

1. **CSP `default-src 'self'` blocks every inline style.** A dynamically appended `<style>` element, a `style=` attribute, and a `<style>` inside an `<iframe srcdoc>` all failed to apply (computed colour stayed at the inherited value). A `blob:` iframe was blocked outright (`contentDocument` came back null).
2. **CSSOM is not blocked.** `new CSSStyleSheet()` + `replaceSync()` + `adoptedStyleSheets` applied correctly in the main document and in a shadow root under the same strict CSP.
3. **The reader route works with the strict CSP untouched.** Stripping the `<style>` out of the engine's preview document, setting the rest as `srcdoc` on `<iframe sandbox="allow-same-origin">`, then constructing the sheet **in the frame's realm** (`new frame.contentWindow.CSSStyleSheet()`) and assigning `frame.contentDocument.adoptedStyleSheets = [sheet]` produced: `text-transform: uppercase` and `font-weight: 700` on `h2.scene-heading`, 31 live rules, `body` in Courier Prime, and a visibly correct monospace screenplay page.
4. **The sandboxed frame is scriptable from the parent and inert inside.** `frame.contentWindow.scrollTo(0, 30)` set `scrollY` to 30; a `<script>` appended into the frame did **not** run (no `allow-scripts`).
5. **Bundled fonts load inside that frame.** `about:srcdoc` resolves relative URLs against the parent document, so `url(fonts/courier-prime-400-latin.woff2)` in the adopted sheet fetched and the frame's `FontFace` reported `status === 'loaded'` under `default-src 'self'`.
6. **`document.fonts.check()` lies.** It returned `true` for "Courier Prime" and "Literata" on a machine where `fc-list` shows neither installed. Font presence must be proven by `await document.fonts.load(...)` then reading the `FontFace.status`, never by `check()`.
7. **The asset protocol is a dead end for the reader.** It renders, but the frame is cross-origin (`contentDocument === null`), so the parent cannot script it, and it cannot reach the app's bundled fonts. It also needs a `protocol-asset` cargo feature and a path scope grant. Rejected.
8. **Streaming stderr from Rust works and needs no new command.** Replacing `.output()` with `.spawn()` and forwarding each `CommandEvent::Stderr` through `app.emit` delivered 6 NDJSON progress lines to the window for `tests/fixtures/screenplay.pdf`, while `run_engine` still resolved with the full stdout JSON. `listen()` succeeded under the existing `core:default` capability. Non-comment Rust went 59 → 75 lines.
9. **Exactly one existing assertion breaks:** `tests/desktop-shell.test.ts` → "the Rust ignores the exit code and reads stdout" → `expect(sidecar).toContain('output.stdout')`. Task 5 replaces it with a stronger rule.
10. **The engine's real `--json` convert answer** is `{ok, title, author, pages, scenes, characters, topCharacters[], warnings[], epubPath, mobiPath?, fountainPath?, previewHtmlPath?, debugPath?}`. A failure is `{ok:false, error:{code, message}}`. `--progress` writes `{"progress":{"stage":"parse"|"render","percent":N}}` lines to stderr, throttled to whole percents, ending at `render`/100.
11. **`src/export/` and `src/settings/` are ported and tested but no CLI reaches them.** The spec's "D only calls it" is not yet true for the Kindle export ladder or the per-script settings sidecar. Tasks 3 and 4 build the missing CLI surface; this is the plan's largest deviation from the spec's assumption and is argued in the Scope section below.

## Scope: where the line falls

The five surfaces are the scope. Two things the SwiftUI app does are **out**, deliberately, and are named here rather than quietly dropped:

- **Cancel during conversion.** `brand/components/progress.html` draws a Cancel button and says "cancel is always present". Cancelling a running sidecar needs a third Rust command (a kill handle), which the two-command pin forbids and the spec calls a design smell. D therefore ships progress **without** Cancel, and the plan says so in `desktop/README.md`. Raise it; do not add the command.
- **"Save as app defaults" / global settings.** The Swift rail promotes a script's settings to `UserDefaults`. There is no cross-platform store here that does not add a Rust plugin and a capability grant. D ships **per-script settings only** (the `.screepub.json` sidecar `src/settings/sidecar.ts` already owns), which is the surface the rail actually spends its time in.

Everything else in the five surfaces is planned. If a task cannot be finished honestly, stop and say so rather than shipping a surface that looks finished.

### Task 1: `--options-json` — formatting options through argv

The window has no filesystem. `--options` takes a file path, so the Tune surface cannot reach the engine at all without this. One flag, parsed by the same `resolveFormatOptions` the file path already uses, so there is exactly one merge rule.

**Files:**
- Modify: `src/cli.ts` (the `parseCliArgs` options table; the `values.options` block around line 324; `USAGE`)
- Test: `tests/cli.test.ts`

**Interfaces:**
- Consumes: `resolveFormatOptions(partial?, base?)` from `src/options.ts`; `fail({code, message})` from `src/cli.ts`.
- Produces: CLI flag `--options-json <json>`. Accepts a JSON object literal. Mutually exclusive with `--options`; a malformed or non-object value fails with code `bad-options`. Later tasks pass `JSON.stringify(settings)` as one argv element.

- [ ] **Step 1: Write the failing tests**

Append to `tests/cli.test.ts`. `runCli` is the existing helper in that file that spawns `bun src/cli.ts` and returns `{stdout, stderr, exitCode}` — reuse it exactly as the neighbouring tests do.

```ts
describe('--options-json', () => {
  test('applies a knob passed as an argv string', async () => {
    const out = await runCli([FIXTURE_PDF, '--json', '--preview-html', previewPath,
      '--options-json', '{"dialogueSideMarginPct":7}']);
    const answer = JSON.parse(out.stdout);
    expect(answer.ok).toBe(true);
    const html = await Bun.file(previewPath).text();
    // Not "it didn't crash": the number we passed has to reach the CSS.
    expect(html).toContain('7%');
    expect(html).not.toContain('20%'); // the default this overrode
  });

  test('clamps out-of-range values instead of trusting them', async () => {
    const out = await runCli([FIXTURE_PDF, '--json', '--preview-html', previewPath,
      '--options-json', '{"dialogueSideMarginPct":999}']);
    expect(JSON.parse(out.stdout).ok).toBe(true);
    const html = await Bun.file(previewPath).text();
    expect(html).toContain('30%'); // resolveFormatOptions' documented ceiling
    expect(html).not.toContain('999%');
  });

  test('rejects a non-object payload with bad-options', async () => {
    const out = await runCli([FIXTURE_PDF, '--json', '--options-json', '[1,2]']);
    const answer = JSON.parse(out.stdout);
    expect(answer.ok).toBe(false);
    expect(answer.error.code).toBe('bad-options');
    expect(answer.error.message).toContain('--options-json');
  });

  test('rejects malformed JSON with bad-options and does not leak the payload', async () => {
    const out = await runCli([FIXTURE_PDF, '--json', '--options-json', '{oops']);
    const answer = JSON.parse(out.stdout);
    expect(answer.error.code).toBe('bad-options');
    expect(answer.error.message).not.toContain('oops');
  });

  test('refuses both --options and --options-json rather than picking one', async () => {
    const out = await runCli([FIXTURE_PDF, '--json', '--options', 'x.json',
      '--options-json', '{}']);
    const answer = JSON.parse(out.stdout);
    expect(answer.error.code).toBe('bad-options');
    expect(answer.error.message).toContain('not both');
  });
});
```

Why these cannot pass vacuously: three of them assert a specific number reaching the rendered CSS, so an implementation that accepted the flag and discarded it fails; the clamp test would fail against a naive `JSON.parse` + spread; the "both" test fails against any implementation that silently prefers one.

```ts
  let format: Record<string, unknown> | undefined;
  if (values.options !== undefined && values['options-json'] !== undefined) {
    fail({
      code: 'bad-options',
      message: 'pass --options or --options-json, not both',
    });
  }
  if (values.options) {
    try {
      format = JSON.parse(await readFile(values.options, 'utf8'));
    } catch {
      // Its own code: "your options file is bad" and "the engine crashed"
      // demand different reactions from the caller, and the raw error
      // would leak a temp path into a user-facing message.
      fail({ code: 'bad-options', message: `cannot read options file ${values.options}` });
    }
  }
  if (values['options-json'] !== undefined) {
    // The app's channel: the window has no filesystem, so its settings
    // arrive as one argv element. The PAYLOAD never reaches the message —
    // it is a whole settings object and would bury the sentence.
    let parsed: unknown;
    try {
      parsed = JSON.parse(values['options-json']);
    } catch {
      fail({ code: 'bad-options', message: '--options-json is not valid JSON' });
    }
    if (typeof parsed !== 'object' || parsed === null || Array.isArray(parsed)) {
      fail({ code: 'bad-options', message: '--options-json must be a JSON object' });
    }
    format = parsed as Record<string, unknown>;
  }
```

### Task 2: `--preview-inline` — the reader's document on stdout

`--preview-html <file>` writes a file the window cannot read: the shell grants no filesystem permission, and the asset protocol was measured to be a dead end (cross-origin, no bundled fonts). The reader's document therefore has to travel inside the one JSON object the window already receives.

**Files:**
- Modify: `src/cli.ts` (`parseCliArgs`, the `--json` result object, `USAGE`)
- Test: `tests/cli.test.ts`

**Interfaces:**
- Consumes: `result.previewHtml` on `ConvertResult` (already produced on every conversion by `src/convert.ts`).
- Produces: CLI flag `--preview-inline` (boolean). With `--json`, the result object gains `previewHtml: string` — the same self-contained document `--preview-html` writes. Without `--json` it is a usage error. Later tasks read `answer.previewHtml`.

```ts
    expect(previewHtml).not.toContain('<link rel="stylesheet"');
```

### Task 3: `screepub settings` — the per-script sidecar, reachable

`src/settings/sidecar.ts` and `src/settings/presets.ts` are ported and tested but nothing reaches them. The Tune surface needs to read a script's saved settings, write them back, and offer the two presets. One verb, shaped exactly like piece B's: a handler that returns a value, and `cli.ts` as the only thing that prints.

**Files:**
- Create: `src/cli-settings.ts`
- Create: `tests/cli-settings.test.ts`
- Modify: `src/cli-devices.ts` (`VERBS`), `src/cli.ts` (verb usage, dispatch), `src/cli-errors.ts` (one code)

**Interfaces:**
- Consumes: `loadScriptSettings(fountainPath, fallback)`, `saveScriptSettings(settings, fountainPath)`, `sidecarPath(fountainPath)` from `src/settings/sidecar.ts`; `DEVICE_PRESETS`, `matchingPreset(settings)` from `src/settings/presets.ts`; `DEFAULT_FORMAT_OPTIONS`, `resolveFormatOptions` from `src/options.ts`; `CliError` from `src/cli-errors.ts`.

  ```ts
  export interface SettingsResult {
    settings: FormatOptions;          // what this script is tuned to now
    defaults: FormatOptions;          // the shipped defaults, for "reset"
    preset: DevicePresetId | null;    // which preset it currently matches
    presets: { id: DevicePresetId; displayName: string; settings: FormatOptions }[];

  }
  ```

```ts
// the sidecar `src/settings/sidecar.ts` already owns. Like the device
// handlers, this RETURNS a result and never prints — cli.ts owns stdout.
import { statSync } from 'node:fs';
import { CliError } from './cli-errors';
import { DEFAULT_FORMAT_OPTIONS, resolveFormatOptions, type FormatOptions } from './options';
import {
  DEVICE_PRESETS,
  matchingPreset,
  type DevicePresetId,
} from './settings/presets';
import { loadScriptSettings, saveScriptSettings, sidecarPath } from './settings/sidecar';

export interface SettingsResult {
  settings: FormatOptions;
  defaults: FormatOptions;
  preset: DevicePresetId | null;
  presets: { id: DevicePresetId; displayName: string; settings: FormatOptions }[];
  sidecar: string;
}

export interface SettingsOptions {
  /** The script's .fountain — the sidecar is named after it. */
  fountain: string;
  /** A PARTIAL FormatOptions as JSON. Overlaid on what is stored, never
   * replacing it, so a window that sends one moved knob moves one knob. */
  set?: string;
}

export function settingsCommand(options: SettingsOptions): SettingsResult {
  let isFile = false;
  try {
    isFile = statSync(options.fountain).isFile();
  } catch {
    isFile = false;
  }
  if (!isFile) {
    throw new CliError('unreadable', `cannot read the script: ${options.fountain}`);
  }

  let settings = loadScriptSettings(options.fountain, DEFAULT_FORMAT_OPTIONS);

  if (options.set !== undefined) {
    let parsed: unknown;
    try {
      parsed = JSON.parse(options.set);
    } catch {
      throw new CliError('bad-settings', '--set is not valid JSON');
    }
    if (typeof parsed !== 'object' || parsed === null || Array.isArray(parsed)) {
      throw new CliError('bad-settings', '--set must be a JSON object');
    }
    // Overlaid on the CURRENT settings, not on the defaults: one moved knob
    // must not silently reset the other seventeen. Clamping is
    // resolveFormatOptions', not a second copy of it.
    settings = resolveFormatOptions(parsed as Record<string, unknown>, settings);
    saveScriptSettings(settings, options.fountain);
  }

  const ids = Object.keys(DEVICE_PRESETS) as DevicePresetId[];
  return {
    settings,
    defaults: DEFAULT_FORMAT_OPTIONS,
    preset: matchingPreset(settings),
    presets: ids.map((id) => ({
      id,
      displayName: DEVICE_PRESETS[id].displayName,
      settings: DEVICE_PRESETS[id].settings,
    })),
    sidecar: sidecarPath(options.fountain),
  };
}
```

```ts
// The `export` verb: the file you would actually put on a reader. `send`
// never converts, and a Kindle never indexes a sideloaded EPUB, so the
// window needs a way to ask for the Kindle rung before it sends. The LADDER
// is src/export/artifact.ts's — this file chooses nothing, it only carries
// the answer out. Returns a value; cli.ts owns stdout.
import { statSync } from 'node:fs';
import { CliError, errorMessage } from './cli-errors';
import { availableFormats, freshKindleArtifact } from './export/artifact';
import { isCalibreAvailable } from './export/calibre';
import { fileExtension, formatLabel, type ExportFormat } from './export/formats';
import { kfxStatus } from './export/kfx';
import { DEFAULT_FORMAT_OPTIONS, resolveFormatOptions, type FormatOptions } from './options';

export interface ExportResult {
  path: string;
  format: ExportFormat;
  extension: string;
  label: string;
  available: ExportFormat[];
  stages: string[];
}

export interface ExportOptions {
  /** An EXISTING .epub — the conversion's primary output. */
  epub: string;
  /** 'epub' (default) or 'kindle'. */
  for?: string;
  /** The script's .fountain, needed only by the MOBI rung. */
  fountain?: string;
  /** This script's settings, as --options-json carries them elsewhere. */
  optionsJson?: string;
}

function readFormat(optionsJson: string | undefined): FormatOptions {
  if (optionsJson === undefined) return DEFAULT_FORMAT_OPTIONS;
  let parsed: unknown;
  try {
    parsed = JSON.parse(optionsJson);
  } catch {
    throw new CliError('bad-options', '--options-json is not valid JSON');
  }
  if (typeof parsed !== 'object' || parsed === null || Array.isArray(parsed)) {
    throw new CliError('bad-options', '--options-json must be a JSON object');
  }
  return resolveFormatOptions(parsed as Record<string, unknown>);
}

export async function exportCommand(options: ExportOptions): Promise<ExportResult> {
  const wanted = options.for ?? 'epub';
  if (wanted !== 'epub' && wanted !== 'kindle') {
    throw new CliError('usage', `--for takes epub or kindle, not "${wanted}"`);
  }

  // The file is checked FIRST, before any toolchain probe: a typo must not
  // pay Calibre's ~1s Python start to be reported.
  let isFile = false;
  try {
    isFile = statSync(options.epub).isFile();
  } catch {
    isFile = false;
  }
  if (!isFile) {
    throw new CliError('unreadable', `cannot read the book to export: ${options.epub}`);
  }

  const calibreAvailable = isCalibreAvailable();
  const available = availableFormats(options.epub, calibreAvailable);
  const format: ExportFormat = wanted;

  if (format === 'epub') {
    const state = { calibreAvailable, kfxReady: false };
    return {
      path: options.epub,
      format,
      extension: fileExtension(format, state),
      label: formatLabel(format, state),
      available,
      stages: [],
    };
  }

  const kfx = await kfxStatus();
  const state = { calibreAvailable, kfxReady: kfx.ready };
  const stages: string[] = [];
  let path: string;
  try {
    path = await freshKindleArtifact({
      epub: options.epub,
      fountainPath: options.fountain ?? null,
      format: readFormat(options.optionsJson),
      calibreAvailable,
      kfxReady: kfx.ready,
      onStage: (stage) => stages.push(stage),
    });
  } catch (err) {
    // The ladder's own sentences are already written for a person
    // (CannotRegenerateError, RegenerationFailedError, CalibreMissingError);
    // passing them through verbatim is the rule this project already keeps
    // for send-failed.
    throw new CliError('export-failed', errorMessage(err));
  }

  return {
    path,
    format,
    extension: fileExtension(format, state),
    label: formatLabel(format, state),
    available,
    stages,
  };
}
```

```rust
//! The engine is `src/cli.ts`, compiled by `tools/build-sidecar.ts` and
//! bundled as a Tauri external binary. Its `--json` contract is that every
//! exit prints exactly one parseable JSON object on stdout — on success and
//! on failure alike. So this file:
//!
//!   * does not parse that object (`serde_json` is not a dependency),
//!   * does not add or remove an argument (the frontend builds the argv),
//!   * does not treat a non-zero exit as a failure, because an engine error
//!     exits 1 *and prints a perfectly good error object*. Stdout is the
//!     contract; the exit code is not.
//!
//! It spawns rather than waits, for ONE reason: the engine writes a line to
//! its diagnostic stream as it works, and a window that only gets the answer
//! at the end cannot draw a moving bar. Each such line is forwarded verbatim
//! under one name. This file never looks inside a line. If a change here
//! needs to know what a line MEANS, the change belongs in `desktop/ui/`.
//!
//! This is deliberately NOT a third command: the two registered commands are
//! unchanged, and the window is granted no new permission.
//!
//! The name below is resolved by Tauri against the bundled external binary;
//! `desktop/README.md` records how that resolution was observed working.

use tauri::{AppHandle, Emitter};
use tauri_plugin_shell::process::CommandEvent;
use tauri_plugin_shell::ShellExt;

/// Must match `SIDECAR_BASENAME` in `tools/sidecar-targets.ts`.
/// `tests/desktop-shell.test.ts` pins the two together.
pub const SIDECAR: &str = "screepub-engine";

/// Every line the engine writes to its diagnostic stream is forwarded under
/// this name, uninspected. The window decides what a line is.
pub const LINE_EVENT: &str = "engine-line";

pub async fn run(app: &AppHandle, args: Vec<String>) -> Result<String, String> {
    let (mut rx, _child) = app
        .shell()
        .sidecar(SIDECAR)
        .map_err(|e| {
            format!(
                "could not find the Screepub engine (looked for a sidecar named {SIDECAR:?}): {e}. \
                 Run `bun tools/build-sidecar.ts --host` to build it."
            )
        })?
        .args(args)
        .spawn()
        .map_err(|e| {
            format!(
                "could not start the Screepub engine (sidecar {SIDECAR:?}): {e}. \
                 Run `bun tools/build-sidecar.ts --host` to build it."
            )
        })?;

    let mut stdout = String::new();
    let mut diagnostics = String::new();
    let mut exit: Option<i32> = None;
    while let Some(event) = rx.recv().await {
        match event {
            CommandEvent::Stdout(bytes) => stdout.push_str(&String::from_utf8_lossy(&bytes)),
            CommandEvent::Stderr(bytes) => {
                let line = String::from_utf8_lossy(&bytes).to_string();
                // Ignoring the result on purpose: a window that has gone
                // away must not turn into an engine failure.
                let _ = app.emit(LINE_EVENT, line.clone());
                diagnostics.push_str(&line);
            }
            CommandEvent::Terminated(status) => exit = status.code,
            _ => {}
        }
    }

    let stdout = stdout.trim().to_string();
    if stdout.is_empty() {
        // Nothing on stdout means the engine died before it could honour
        // its own contract. What it said on the way down is all that is left.
        return Err(format!(
            "the Screepub engine exited with {exit:?} and printed nothing: {}",
            diagnostics.trim()
        ));
    }
    Ok(stdout)
}
```

```ts
// desktop/ui/tokens.css, generated from brand/tokens.json and the scale
// blocks of brand/tokens.css.
//
// Why a generated copy and not an @import: desktop/ui has no build step and
// tauri.conf.json's frontendDist embeds only what is under desktop/ui/, so a
// path into brand/ 404s even under `cargo run`. The copy is therefore
// unavoidable; a copy a person maintains is not. tests/desktop-tokens.test.ts
// regenerates this file and fails on any difference.
//
// The seven colours in CORE_IN_STYLE_CSS are deliberately EXCLUDED: they live
// in desktop/ui/style.css, where tests/desktop-shell.test.ts pins them to
// brand/tokens.json in its own way. Declaring them twice would create a
// "which block wins" question with no good answer.
import { readFileSync, writeFileSync } from 'node:fs';
import { join } from 'node:path';

export const CORE_IN_STYLE_CSS = [
  'paper', 'ink', 'ink-muted', 'ink-on-brass', 'brass', 'ground', 'alarm',
] as const;

const HEADER = `/* GENERATED by tools/build-desktop-tokens.ts — do not edit.
 * Source of truth: brand/tokens.json (colours) and brand/tokens.css (scales).
 * The seven colours desktop/ui/style.css declares are excluded on purpose;
 * see the generator for why. Regenerate with:
 *   bun tools/build-desktop-tokens.ts
 */
`;

/** The non-colour blocks, lifted verbatim from brand/tokens.css so the two
 *  files cannot describe different scales. Keyed by the comment that opens
 *  each block there. */
const SCALE_MARKERS = [
  '--font-structure:',
  '--text-fine:',
  '--radius-mark:',
  '--motion-press:',
  '--space-1:',
  '--measure:',
];

function scaleLines(brandCss: string, colorNames: Set<string>): string[] {
  const root = brandCss.slice(brandCss.indexOf(':root'), brandCss.indexOf('@media'));
  const lines: string[] = [];
  for (const line of root.split('\n')) {
    const declaration = line.trim();
    const match = /^--([\w-]+):\s*(.+);$/.exec(declaration);
    if (!match) continue;
    const [, name] = match;
    // Colours come from tokens.json, which is the source of truth for them.
    // Matched by EXACT NAME, never by prefix: `--hole` is a colour and
    // `--hole-center` is a geometry value, and a prefix test would silently
    // drop the second one and put the brads in the wrong place.
    if (colorNames.has(name)) continue;
    lines.push(`  ${declaration}`);
  }
  // Guard the lift: brand/tokens.css moving its scales would otherwise make
  // this generator silently produce a file with no sizes in it.
  for (const marker of SCALE_MARKERS) {
    if (!lines.some((l) => l.includes(marker))) {
      throw new Error(`brand/tokens.css no longer declares ${marker}`);
    }
  }
  return lines;
}

export function buildDesktopTokens(tokensJson: string, brandCss: string): string {
  const colors = JSON.parse(tokensJson).colors as Record<
    string,
    { light: string; dark: string }
  >;
  const excluded = new Set<string>(CORE_IN_STYLE_CSS);
  const names = Object.keys(colors).filter((n) => !excluded.has(n));

  const light = names.map((n) => `  --${n}: ${colors[n].light};`);
  const dark = names
    .filter((n) => colors[n].dark !== colors[n].light)
    .map((n) => `    --${n}: ${colors[n].dark};`);

  return (
    `${HEADER}\n:root {\n` +
    `${light.join('\n')}\n\n` +
    `${scaleLines(brandCss, new Set(Object.keys(colors))).join('\n')}\n` +
    `}\n\n` +
    `@media (prefers-color-scheme: dark) {\n  :root {\n${dark.join('\n')}\n  }\n}\n`
  );
}

if (import.meta.main) {
  const repo = join(import.meta.dir, '..');
  const out = buildDesktopTokens(
    readFileSync(join(repo, 'brand', 'tokens.json'), 'utf8'),
    readFileSync(join(repo, 'brand', 'tokens.css'), 'utf8'),
  );
  writeFileSync(join(repo, 'desktop', 'ui', 'tokens.css'), out);
  console.log('wrote desktop/ui/tokens.css');
}
```

```js
// these, so there is exactly one place that sets text — and therefore no

/** el('p', { class: 'x', onclick: fn }, 'text', childNode) */
export function el(tag, props = {}, ...children) {
  const node = document.createElement(tag);
  for (const [key, value] of Object.entries(props)) {
    if (value === null || value === undefined || value === false) continue;
    if (key.startsWith('on') && typeof value === 'function') {
      node.addEventListener(key.slice(2), value);
    } else if (key === 'class') {
      node.className = value;
    } else if (key === 'disabled' || key === 'hidden' || key === 'checked' || key === 'value') {
      node[key] = value;
    } else {
      node.setAttribute(key, String(value));
    }
  }
  for (const child of children.flat()) {
    if (child === null || child === undefined || child === false) continue;
    node.append(typeof child === 'string' ? document.createTextNode(child) : child);
  }
  return node;
}

export function clear(node) {
  while (node.firstChild) node.removeChild(node.firstChild);
  return node;
}

/** Always textContent. A script's title, a device's name and the engine's
 *  messages are all data from outside this window; none of it is markup. */
export function text(node, value) {
  node.textContent = value === null || value === undefined ? '' : String(value);
  return node;
}
```

```js
// The window's whole share of the work: build an argv, hand it to Rust,
// parse what comes back.
//
// This is the ONLY file that touches Tauri, and the only file that knows an
// engine flag. The Rust does not know these flags and must not learn them:
// --json is this file's responsibility, and so is deciding what the answer
// means. See ADR 2026-09-12: Rust is a window, not a brain.
// tests/desktop-shell.test.ts and tests/desktop-ui.test.ts read this file
// by name; keep every invoke() and every flag literal here.

const invoke = window.__TAURI__.core.invoke;
const listen = window.__TAURI__.event.listen;

/** Every argv this window ever builds. One place, so a flag cannot be spelled
 *  two ways, and so a reviewer can read the whole contract at once. */
export const argv = {
  version: () => ['--version', '--json'],

  /** The first conversion. --progress makes the engine narrate to stderr,
   *  which the shell forwards as `engine-line`; --preview-inline puts the
   *  reader's document in the answer, because the window cannot read files. */
  convert: (path, { force = false, optionsJson = null } = {}) =>
    [path, '--json', '--progress', '--preview-inline',
      force ? '--force' : null,
      optionsJson ? '--options-json' : null, optionsJson].filter((a) => a !== null),

  /** A re-render from the cached .fountain, writing the library EPUB back in
   *  place so what gets sent stays what was previewed. */
  reconvert: (fountain, epubPath, optionsJson) =>
    [fountain, '--json', '--preview-inline', '-o', epubPath,
      '--options-json', optionsJson],

  devices: () => ['devices', '--json'],

  send: (file, deviceId = null) =>
    ['send', file, '--json', deviceId ? '--device' : null, deviceId]
      .filter((a) => a !== null),

  settings: (fountain, set = null) =>
    ['settings', fountain, '--json', set ? '--set' : null, set].filter((a) => a !== null),

  export: (epub, { forFormat, fountain = null, optionsJson = null }) =>
    ['export', epub, '--json', '--for', forFormat,
      fountain ? '--fountain' : null, fountain,
      optionsJson ? '--options-json' : null, optionsJson].filter((a) => a !== null),
};

/** Run the engine and parse its one line of stdout.
 *  Throws an Error whose message is fit to show a person. */
export async function runEngine(args) {
  let stdout;
  try {
    stdout = await invoke('run_engine', { args });
  } catch (message) {
    // Rust rejected: it could not find or start the binary at all.
    throw new Error(String(message));
  }
  try {
    return JSON.parse(stdout);
  } catch {
    // The engine printed something that is not its contract. Show it raw
    // rather than swallowing it — this is how a dropped --json presents.
    throw new Error(`the engine did not answer in JSON:\n${stdout}`);
  }
}

/** Ask the OS for a screenplay. Null when the reader cancelled. */
export async function pickScreenplay() {
  const path = await invoke('pick_file');
  return path ?? null;
}

/** Every diagnostic line the engine writes, verbatim, as it writes it.
 *  Resolves to the function that stops listening. */
export function onEngineLine(handler) {
  return listen('engine-line', (event) => handler(String(event.payload)));
}

/** The progress lines, decoded. The payload is whatever the OS handed the
 *  Rust, so one event may carry several lines or a partial one; anything
 *  that is not a progress object is ignored rather than thrown, because a
 *  stray warning on stderr must not take a conversion down with it. */
export function onProgress(handler) {
  return onEngineLine((payload) => {
    for (const line of payload.split('\n')) {
      const trimmed = line.trim();
      if (trimmed === '') continue;
      try {
        const parsed = JSON.parse(trimmed);
        if (parsed && parsed.progress) handler(parsed.progress);
      } catch {
        // Not JSON, not ours.
      }
    }
  });
}
```

```js
    for (let hop = 1; hop <= SURFACES.length; hop += 1) {
      const next = SURFACES[(from + step * hop + SURFACES.length * hop) % SURFACES.length];

      if (button.disabled) continue; // a dimmed surface is not a stop
      setSurface(next.id);
      button.focus();
      return;
    }
  });

    sheet,
    setSurface,
    onSurface: (handler) => handlers.push(handler),
    enable: (id, on) => { document.getElementById(`tab-${id}`).disabled = !on; },
```

```js
import { el, clear, text } from './dom.js';

/** The heading names the CAUSE, not the failure. "Scanned PDF, no text"
 *  tells you what to do next; "Something went wrong" does not. Every code
 *  src/cli-errors.ts can return on the conversion path has an entry, so a
 *  real failure never renders with a blank heading. */

  scanned: 'Int. scanned pdf, no text - day',
  'not-screenplay': 'Int. not a screenplay - day',

  /mac/i.test(navigator.userAgentData?.platform ?? navigator.platform) ? '⌘O' : 'Ctrl+O';

export function dragOver(on) {
  pane?.querySelector('.well')?.classList.toggle('well-targeted', on);

export async function convertPath(path, { force = false } = {}) {
  drawProgress(path);
  let answer;
  try {
    answer = await runEngine(argv.convert(path, { force }));
  } catch (err) {
    drawFailure({ code: 'internal', message: err.message }, path);
    return;
  } finally {
    (await unlistenProgress)?.();
    unlistenProgress = null;
  }
  if (answer.ok) drawResult(path, answer);
  else drawFailure(answer.error, path);
}

async function pickFileThenConvert() {
  const path = await pickScreenplay();
  // desktop/README.md records that the webview does not always take keyboard
  // focus back when the native dialog closes. Asking for it costs nothing
  // and is the difference between a usable keyboard and a dead one.
  chooseButton?.focus();

  await convertPath(path);
}

function drawProgress(path) {

  pane.dataset.state = 'working';

    el('div', { class: 'meter' },
      el('div', { class: 'track' }, fill),
      readOut),
    el('p', { class: 'sign-off' }, 'Please stand by:'),
  );
}

  pane.dataset.state = 'done';
  ctx.state.script = {
    path,
    title: answer.title,
    author: answer.author ?? null,
    pages: answer.pages,
    scenes: answer.scenes,
    characters: answer.characters,
    warnings: answer.warnings ?? [],

    el('div', { class: 'announce' },
      el('p', { class: 'book-title' }, answer.title),
      answer.author ? el('p', { class: 'book-by' }, `(by ${answer.author})`) : null,
      // The counts are the fastest way to confirm the parse was right: a
      // wrong character count means the cues were misread.
      el('p', { class: 'book-count' },
        `${answer.pages} pages. ${answer.scenes} scenes.\n` +
        `${answer.characters} speaking characters.`),
      ...(answer.warnings ?? []).map((w) => el('p', { class: 'caption' }, `(${w})`)),
    ),
    el('div', { class: 'send' },
      el('button', { type: 'button', class: 'btn btn-brad', onclick: () => ctx.goTo('send') },
        'Send to a reader'),
      el('div', { class: 'asides' },
        el('button', { type: 'button', class: 'btn-quiet', onclick: () => ctx.goTo('read') },

  clear(pane);
  pane.dataset.state = 'failed';
  const ways = el('div', { class: 'ways' });
```

```js
/** OS drag-and-drop. Tauri intercepts it, so the HTML5 drop event never
 *  fires and the PATHS — which is all the engine can use — arrive here. */
export function onFileDrag({ over, drop }) {
  listen('tauri://drag-enter', () => over(true));
  listen('tauri://drag-leave', () => over(false));
  listen('tauri://drag-drop', (event) => {
    over(false);
    const paths = event.payload?.paths ?? [];
    if (paths.length > 0) drop(paths[0]);
  });
}
```

```js
});
```

```js
// Read: the converted script, with its scene rail.
//
// The engine produces this document (tokensToPreviewHtml) and its stylesheet
// (src/epub/css.ts). The reader renders exactly those, so a formatting
// decision cannot disagree between this window and the EPUB a reader
// actually gets. Nothing here styles a screenplay.
//
// HOW, and why it is not simpler than this — all four routes were measured
// in a real window before this was written:
//
//   * The window's CSP is `default-src 'self'`, which blocks every inline
//     style, INCLUDING a <style> inside an <iframe srcdoc>: srcdoc frames
//     inherit the parent's policy. Leaving the engine's <style> in place
//     renders an unstyled script with no error anywhere.
//   * CSSOM is not blocked. So the <style> is lifted out of the document
//     and its text is adopted as a constructed stylesheet instead — same
//     bytes, same rules, nothing rewritten.
//   * The sheet must be constructed in the FRAME's realm. A CSSStyleSheet
//     built in this document is rejected when adopted into another.
//   * The asset protocol renders but is cross-origin: the parent cannot
//     script the frame (no scroll keeping, no rail) and the frame cannot
//     reach the bundled fonts. Rejected.
//
// The frame is an iframe rather than a div because the engine's stylesheet
// has `html, body` rules, and an iframe is the only container that has an
// html and a body of its own to give them.
import { el, clear, text } from './dom.js';

/** The faces the engine's CSS asks for by name. Nothing inside the frame
 *  knows where those files are, so the reader says. This adds a face; it
 *  changes no rule the engine wrote. */
const FONT_CSS = `
@font-face { font-family: "Courier Prime"; font-weight: 400; font-style: normal;
  src: url(fonts/courier-prime-400-latin.woff2) format("woff2"); }
@font-face { font-family: "Courier Prime"; font-weight: 700; font-style: normal;
  src: url(fonts/courier-prime-700-latin.woff2) format("woff2"); }
@font-face { font-family: "Literata"; font-weight: 400; font-style: normal;
  src: url(fonts/literata-400-latin.woff2) format("woff2"); }
`;

let ctx = null;
let pane = null;
let frame = null;
let rail = null;
let pendingScroll = 0;

export function mount(node, context) {
  pane = node;
  ctx = context;
  draw();
}

export function scriptChanged() {
  if (ctx.state.script) render(ctx.state.script.previewHtml);
  else draw();
}

export function show() {
  if (ctx.state.script && frame && !frame.dataset.rendered) {
    render(ctx.state.script.previewHtml);
  }
}

function draw() {
  clear(pane);
  if (!ctx.state.script) {
    pane.append(
      el('h2', { class: 'slug' }, 'Int. empty reader - day'),
      el('p', { class: 'prose' }, 'Convert a script and it opens here.'),
    );
    frame = null;
    rail = null;
    return;
  }

  rail = el('nav', { class: 'scene-rail', 'aria-label': 'Scenes' });
  frame = el('iframe', {
    class: 'script-frame',
    title: ctx.state.script.title,
    // Same origin so the parent can keep the reader's place and build the
    // rail; no allow-scripts, so nothing inside the document can run.
    sandbox: 'allow-same-origin',
  });
  frame.addEventListener('load', dress);

  pane.append(
    el('div', { class: 'reader' }, frame, rail),
  );
  render(ctx.state.script.previewHtml);
}

export function render(previewHtml) {
  if (!frame) { draw(); return; }
  // Where the reader was, so a re-render does not throw them back to FADE IN.
  pendingScroll = frame.contentWindow ? frame.contentWindow.scrollY : 0;

  const parsed = new DOMParser().parseFromString(previewHtml, 'text/html');
  const styleEl = parsed.querySelector('style');
  frame.dataset.css = styleEl ? styleEl.textContent : '';
  if (styleEl) styleEl.remove();
  frame.dataset.rendered = '1';
  frame.setAttribute('srcdoc', `<!doctype html>${parsed.documentElement.outerHTML}`);
}

function dress() {
  const doc = frame.contentDocument;
  const win = frame.contentWindow;
  if (!doc || !win) return;

  const sheet = new win.CSSStyleSheet();
  sheet.replaceSync(`${FONT_CSS}\n${frame.dataset.css ?? ''}`);
  doc.adoptedStyleSheets = [sheet];

  win.scrollTo(0, pendingScroll);
  buildRail(doc, win);
}

/** The rail is the engine's own scene sections, in the engine's own order.
 *  Reading them off the rendered document rather than re-parsing anything
 *  is what keeps this from becoming a second opinion about what a scene is. */
function buildRail(doc, win) {
  clear(rail);
  const scenes = [...doc.querySelectorAll('section.scene')];
  if (scenes.length === 0) {
    rail.append(el('p', { class: 'caption' }, 'No scene headings in this script.'));
    return;
  }
  rail.append(el('p', { class: 'state-label' }, `${scenes.length} scenes`));
  for (const scene of scenes) {
    const heading = scene.querySelector('h2.scene-heading');
    const label = heading ? heading.textContent.trim() : scene.id;
    rail.append(el('button', {
      type: 'button',
      class: 'scene-link',
      onclick: () => scene.scrollIntoView({
        behavior: ctx.state.reducedMotion ? 'auto' : 'smooth',
        block: 'start',
      }),
    }, label));
  }
}
```

```js
    return el('div', { class: 'knob knob-range' },
      el('label', { for: id }, knob.label), readOut, control,
      knob.help ? el('p', { class: 'caption' }, knob.help) : null,
    );
  } else {
    control = el('select', { id, onchange: (e) => change(knob.key, e.target.value) },
      ...knob.choices.map(([v, label]) =>
        el('option', { value: v, selected: v === value }, label)),
    );
  }

  return el('div', { class: 'knob' },
    el('label', { for: id }, knob.label), control,
    knob.help ? el('p', { class: 'caption' }, knob.help) : null,
  );
}

function applyAll(next) {
  settings = { ...next };
  ctx.state.script.settings = settings;
  draw();
  schedule(settings);
}

function change(key, value) {
  settings = { ...settings, [key]: value };
  ctx.state.script.settings = settings;
  // cueAlignment shows and hides two sliders, so its change redraws.
  if (key === 'cueAlignment') draw();
  schedule({ [key]: value });
}

/** Debounced, and serialised behind whatever is already running: a knob
 *  dragged across its range fires a hundred times, and a slow early render
 *  finishing last would leave stale files on disk. */
function schedule(partial) {
  clearTimeout(timer);
  timer = setTimeout(() => {
    const previous = pending;
    pending = (async () => {
      await previous.catch(() => {});
      await saveAndRender(partial);
    })();
  }, 300);
}

async function saveAndRender(partial) {
  const script = ctx.state.script;
  if (!script?.fountainPath) return;
  text(statusLine, 'rebuilding…');
  try {
    const saved = await runEngine(argv.settings(script.fountainPath, JSON.stringify(partial)));
    settings = saved.settings;
    script.settings = settings;
    const answer = await runEngine(
      argv.reconvert(script.fountainPath, script.epubPath, JSON.stringify(settings)),
    );
    if (!answer.ok) {
      text(statusLine, answer.error.message);
      statusLine.classList.add('bad');
      return;
    }
    statusLine.classList.remove('bad');
    script.previewHtml = answer.previewHtml ?? script.previewHtml;
    script.pages = answer.pages ?? script.pages;
    renderReader(script.previewHtml);
    text(statusLine, 'saved, and the book on disk was rebuilt to match');
  } catch (err) {
    text(statusLine, err.message);
    statusLine.classList.add('bad');
  }
}
```

```js
// Send: what is plugged in, and the file that should go on it.
//
// The window knows nothing about devices. `screepub devices` says what is
// connected, `screepub export` says which file a Kindle should get (KFX →
// AZW3 → MOBI, best rung this machine can reach), and `screepub send` moves
// it. Each of those is tested TypeScript shared with the CLI; this file
// draws their answers.
import { runEngine, argv } from './app.js';
import { el, clear, text } from './dom.js';

/** The project's own stated limit, on the surface rather than in a README:
 *  only a Kindle, on a Mac, has ever been plugged in. Everything else is
 *  built and code-tested. Saying so is the difference between a promise and
 *  a claim. */
const UNPROVEN = 'never been tested on real hardware';
const PROVEN_KINDS = new Set(['kindle']);

let ctx = null;
let pane = null;
let list = null;
let statusLine = null;
let poll = null;

export function mount(node, context) {
  pane = node;
  ctx = context;
  draw();
}

export function scriptChanged() { draw(); }

export function show() {
  draw();
  refresh();
  // A reader plugs something in while looking at this surface; the list has
  // to notice. Two seconds is under a person's patience and well above the
  // cost of a mount scan.
  poll = setInterval(refresh, 2000);
}

export function hide() {
  clearInterval(poll);
  poll = null;
}

function draw() {
  clear(pane);
  if (!ctx.state.script) {
    pane.append(
      el('h2', { class: 'slug' }, 'Int. nothing to send - day'),
      el('p', { class: 'prose' }, 'Convert a script and it can go to a reader from here.'),
    );
    list = null;
    return;
  }
  list = el('div', { class: 'devices' },
    el('p', { class: 'caption' }, 'Looking for readers…'));
  statusLine = el('p', { class: 'caption' }, '');
  pane.append(
    el('h2', { class: 'slug' }, 'Int. your desk - night'),
    el('p', { class: 'prose' },
      'Plug a reader in over USB. Screepub builds the file that reader can ' +
      'actually open, then copies it across — nothing leaves this computer.'),
    list,
    statusLine,
  );
}

async function refresh() {
  if (!list) return;
  let answer;
  try {
    answer = await runEngine(argv.devices());
  } catch (err) {
    clear(list);
    list.append(el('p', { class: 'fault-body' }, err.message));
    return;
  }
  ctx.state.devices = answer.devices ?? [];
  clear(list);

  if (ctx.state.devices.length === 0) {
    // Nothing connected is an answer, not an error — the same position
    // `screepub devices` itself takes.
    list.append(
      el('p', { class: 'state-label' }, 'Nothing connected'),
      el('p', { class: 'prose' },
        'no reader is plugged in. Connect one over USB and it appears here.'),
    );
    return;
  }

  for (const device of ctx.state.devices) {
    list.append(deviceRow(device));
  }
}

function deviceRow(device) {
  const button = el('button', { type: 'button', class: 'btn btn-brad' },
    `Send to ${device.name}`);
  button.addEventListener('click', () => sendTo(device, button));
  return el('div', { class: 'device-row' },
    el('div', { class: 'device-what' },
      el('p', { class: 'device-name' }, device.name),
      el('p', { class: 'device-where' }, device.volume ?? device.kind),
      PROVEN_KINDS.has(device.kind)
        ? null
        : el('p', { class: 'device-caveat' }, `${device.kind} has ${UNPROVEN}.`),
    ),
    button,
  );
}

async function sendTo(device, button) {
  const script = ctx.state.script;
  button.disabled = true;
  statusLine.classList.remove('bad');
  try {
    // A Kindle never indexes a sideloaded EPUB, so it gets the ladder's
    // answer instead. Everything else takes the EPUB it was given.
    const forFormat = device.kind === 'kindle' ? 'kindle' : 'epub';
    text(statusLine, forFormat === 'kindle' ? 'building the Kindle file…' : 'preparing…');
    const built = await runEngine(argv.export(script.epubPath, {
      forFormat,
      fountain: script.fountainPath,
      // This script's own tuning, never the defaults: a rebuild with the
      // defaults would silently lose the reader's formatting.
      optionsJson: script.settings ? JSON.stringify(script.settings) : null,
    }));
    if (!built.ok) throw new Error(built.error.message);
    for (const stage of built.stages ?? []) text(statusLine, stage);

    text(statusLine, `copying to ${device.name}…`);
    const sent = await runEngine(argv.send(built.path, device.id));
    if (!sent.ok) throw new Error(sent.error.message);

    // The verb stays constant through the flow: Send produced Sent.
    text(statusLine, sent.uploaded
      ? `Sent to ${device.name}.`
      : `Sent to ${device.name} — ${sent.destination}. Eject before unplugging.`);
  } catch (err) {
    // The engine's own sentence. Every one of these is already written for
    // a person: "Can't rebuild the Kindle file — the script's .fountain is
    // missing.", "no reader is connected", and so on.
    text(statusLine, err.message);
    statusLine.classList.add('bad');
  } finally {
    button.disabled = false;
  }
}
```

- [ ] **Step 3: Write `tools/build-desktop-notes.ts`**

```ts
// desktop/ui/notes.js, compiled from docs/releases/<version>.md.
//
// The window has no filesystem and no markdown library, and it must work
// offline, so the notes are turned into data at build time. The subset is
// exactly the shape docs/release-notes-template.md produces: one H1, a
// headline paragraph, H2 sections, and bold-led bullets. Anything outside
// that shape is a template change, and this throws rather than dropping it
// silently. tests/desktop-notes.test.ts regenerates and compares.
import { readFileSync, writeFileSync } from 'node:fs';
import { join } from 'node:path';

export interface ReleaseNotes {
  version: string;
  headline: string;
  sections: { title: string; items: { lead: string; body: string }[] }[];
}

const BULLET = /^- \*\*(.+?)\*\*\s*(.*)$/;

/** Strip the inline markup the template uses, leaving the sentence. Code
 *  spans and links keep their TEXT, because the text is the sentence. */
function plain(value: string): string {
  return value
    .replace(/\[([^\]]+)\]\([^)]+\)/g, '$1')
    .replace(/\*\*([^*]+)\*\*/g, '$1')
    .replace(/`([^`]+)`/g, '$1')
    .trim();
}

export function parseReleaseNotes(version: string, markdown: string): ReleaseNotes {
  const lines = markdown.split('\n');
  let headline = '';
  const sections: ReleaseNotes['sections'] = [];
  let current: ReleaseNotes['sections'][number] | null = null;
  let open: { lead: string; body: string[] } | null = null;

  const closeItem = () => {
    if (open && current) {
      current.items.push({ lead: open.lead, body: plain(open.body.join(' ')) });
    }
    open = null;
  };

  for (const raw of lines) {
    const line = raw.trimEnd();
    if (line.startsWith('# ')) continue; // the title; version carries it
    if (line.startsWith('## ')) {
      closeItem();
      current = { title: line.slice(3).trim(), items: [] };
      sections.push(current);
      continue;
    }
    const bullet = BULLET.exec(line);
    if (bullet) {
      closeItem();
      open = { lead: plain(bullet[1]), body: [bullet[2]] };
      continue;
    }
    if (open && /^\s+\S/.test(raw)) {
      // A wrapped continuation of the bullet above. Joined with a space,
      // because the newline is the file's margin, not the sentence's.
      open.body.push(line.trim());
      continue;
    }
    closeItem();
    if (line.trim() !== '' && current === null && headline === '') {
      headline = plain(line);
    }
  }
  closeItem();

  if (headline === '') throw new Error(`${version}.md has no headline paragraph`);
  if (sections.length === 0) throw new Error(`${version}.md has no ## sections`);
  return { version, headline, sections };
}

export function renderNotesModule(notes: ReleaseNotes): string {
  return (
    '// GENERATED by tools/build-desktop-notes.ts — do not edit.\n' +
    '// Source: docs/releases/' + notes.version + '.md\n' +
    '// Regenerate with: bun tools/build-desktop-notes.ts\n' +
    'export const RELEASE = {\n' +
    `  version: ${JSON.stringify(notes.version)},\n` +
    `  headline: ${JSON.stringify(notes.headline)},\n` +
    '  sections: [\n' +
    notes.sections
      .map(
        (section) =>
          '    {\n' +
```

```markdown
### Why the reader is an iframe with an adopted stylesheet

The window's CSP is `default-src 'self'`, which blocks **every** inline
style — including a `<style>` inside an `<iframe srcdoc>`, because srcdoc
frames inherit the parent's policy. Measured, not assumed: an engine preview
dropped into a srcdoc frame renders completely unstyled, with no error
anywhere.

CSSOM is not blocked. So `read.js` lifts the `<style>` out of the engine's
document and adopts its text as a constructed stylesheet instead — the same
bytes, nothing rewritten. Three details are load-bearing:

- The sheet must be constructed **in the frame's realm**
  (`new frame.contentWindow.CSSStyleSheet()`); one built in the parent is
  rejected on adoption.
- The frame is `sandbox="allow-same-origin"` with **no** `allow-scripts`, so
  the parent can keep the reader's scroll position and build the scene rail,
  while nothing inside the document can run.
- The engine's CSS asks for "Courier Prime" by name and nothing inside the
  frame says where that file is, so `read.js` supplies the `@font-face`
  rules. `about:srcdoc` resolves relative URLs against the parent, so
  `url(fonts/…)` reaches the bundled subsets under the strict CSP.

The asset protocol was tried and rejected: it renders, but the frame is
cross-origin, so the parent cannot script it and it cannot reach the bundled
fonts. It also needs a `protocol-asset` cargo feature and a path-scope grant.

### Fonts

Courier Prime and Literata are bundled as the same six WOFF2 subsets the
website self-hosts. **Do not use `document.fonts.check()` to verify one is
present** — it was measured returning `true` on a machine where `fc-list`
showed neither installed. `await document.fonts.load(...)` and then read the
`FontFace.status`.

### What piece D does not do

- **No Cancel during conversion** (see the progress section above).
- **No global "app defaults"** — settings are per script, in the sidecar
  `src/settings/sidecar.ts` owns. A cross-platform preference store would
  mean a new Tauri plugin and a new capability grant.
- **No auto-update.** Notes says so on the surface.
```
